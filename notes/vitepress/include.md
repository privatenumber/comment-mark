# Include directive

At the audited revision, VitePress expands `<!-- @include: path -->` before rendering when the render environment has a file path (`env.realPath` or `env.path`); without one, the directive is left unexpanded ([source](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L51-L55)). It uses the [directive regex](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L27-L29) and [render wrapper](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L38-L60). A path that starts with `@` resolves from `srcDir`, with the `@` and an optional following `/` removed, so `@/foo.md` and `@foo.md` both resolve to `foo.md` in `srcDir` ([source](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L92-L94)). Any other path resolves from the including file's directory. [Source](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L87-L94).

An optional `{start,end}` suffix selects a one-based inclusive line range; either endpoint can be omitted. An optional `#region` selects named regions and falls back to a heading anchor if no region matches. A range can be applied after region selection. [Source](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L127-L155). Region matching recognizes several comment styles using patterns derived from VS Code folding markers. It tries all styles for each file, making the set a superset rather than an exact reproduction of every language service. [Source](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/regions.ts#L20-L67).

For `.md` files, the plugin strips frontmatter before selection except when a range is specified without a region. In that case it keeps frontmatter so line numbers refer to the original file. [Source](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L118-L123).

The plugin expands included content recursively and leaves an include directive unchanged when its target is the current file or an ancestor. Reuse in a sibling branch is allowed. It adds each attempted path to `env.includes` before reading, allowing a watcher to detect a subsequently created file. [Cycle and dependency handling](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L96-L102), [recursive call](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L158-L167).

Missing files, directories, missing regions or headings, and invalid ranges go through `fail`: by default it throws; with `silent` it warns and substitutes an empty string. Other read errors are rethrown. [Failure handling](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L81-L85), [read errors](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L104-L115), [selection errors](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L127-L155).

Relative image and link URLs in included Markdown are rebased by default. The plugin inserts rebasing markers only for Markdown includes on their own line outside fences; its renderer uses those markers to rewrite dot-relative URLs, excluding destinations resolved from frontmatter. [Marker conditions](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L170-L181), [renderer rules](https://github.com/vuejs/vitepress/blob/74f9d1d309599fd81dc7f1864da8201e0bbd2420/src/node/markdown/plugins/include.ts#L239-L281).

**Relevance to comment-mark:** [File inclusion](../comment-mark/file-inclusion.md) currently reads whole files from an explicit base directory without recursive expansion.
